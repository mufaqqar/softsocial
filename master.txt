MASTER PROMPT
SOCIAL MEDIA TEAM MANAGEMENT & PUBLISHING SYSTEM
3-PHASE DEVELOPMENT PLAN

PROJECT OBJECTIVE
Build a professional self-hosted social media management system using:
- Next.js
- TypeScript
- App Router
- Tailwind CSS
- shadcn/ui
- PostgreSQL
- Prisma ORM
- Redis/BullMQ only in Phase 3
- Official Meta/Facebook APIs only in Phase 3
- Official LinkedIn APIs only in Phase 3
- OAuth only in Phase 3
- Docker

The system manages multiple Facebook Pages and LinkedIn profiles/pages with a team.

IMPORTANT:
Build exactly 3 phases.

PHASE 1 = MANUAL MANAGEMENT
PHASE 2 = CALENDAR + SCHEDULING
PHASE 3 = AUTOMATIC API PUBLISHING

Do not build Phase 3 first.

============================================================
PHASE 1 - MANUAL SOCIAL MEDIA MANAGEMENT
============================================================

PURPOSE

Create a simple team dashboard where I can:
1. Add multiple Facebook profiles/pages manually.
2. Add multiple LinkedIn profiles/pages manually.
3. Add team members.
4. Create posts.
5. Select multiple social profiles/pages for each post.
6. Assign posts/tasks to team members.
7. Team members manually copy the content and publish it on Facebook/LinkedIn.
8. Team members mark each target as completed.

NO API AUTOMATION IN PHASE 1.
NO FACEBOOK OAUTH.
NO LINKEDIN OAUTH.
NO AUTOMATIC PUBLISHING.

The purpose is to create the internal management system first.

PHASE 3 - AUTOMATIC FACEBOOK + LINKEDIN PUBLISHING
============================================================

PURPOSE

Now introduce automatic publishing.

The Phase 2 calendar becomes the source of publishing jobs.

When the scheduled time arrives, the system automatically publishes
to the selected Facebook Page or LinkedIn Organization using official APIs.

------------------------------------------------------------
3.1 OFFICIAL API ONLY
------------------------------------------------------------

Use:
Official Meta/Facebook APIs
Official LinkedIn APIs

Never use:
- Selenium
- Puppeteer login automation
- Playwright login automation
- Scraping
- Cookie automation
- Fake browser sessions

------------------------------------------------------------
3.2 FACEBOOK / META OAUTH
------------------------------------------------------------

Implement Meta OAuth.

Flow:
Connect Meta Account
-> OAuth
-> Meta authentication
-> Retrieve authorized Pages
-> Show Pages
-> Select Pages
-> Save SocialConnection
-> Save SocialProfiles

Before implementation, check current official Meta documentation for:
- API version
- OAuth
- permissions/scopes
- Page publishing
- media publishing
- App Review

Do not assume old permissions are valid.

------------------------------------------------------------
3.3 LINKEDIN OAUTH
------------------------------------------------------------

Implement LinkedIn OAuth.

Flow:
Connect LinkedIn
-> Authenticate
-> Retrieve authorized organizations/pages where supported
-> Select
-> Save SocialConnection
-> Save SocialProfiles

Verify current LinkedIn API capabilities before implementation.

------------------------------------------------------------
3.7 AUTOMATIC PUBLISHING
------------------------------------------------------------

At scheduled time:

1. Load PostTarget.
2. Load Post.
3. Load SocialProfile.
4. Load SocialConnection.
5. Validate permissions.
6. Validate token.
7. Validate content.
8. Validate media.
9. Publish through provider.
10. Store provider response.
11. Mark target PUBLISHED.
12. Update overall Post status.

------------------------------------------------------------
3.8 REDIS + BULLMQ
------------------------------------------------------------

Use:
Redis
BullMQ

Separate worker process.

Do not use setTimeout for production scheduling.

Jobs should contain IDs only:
postId
workspaceId
postTargetId
socialProfileId

Never put access tokens into Redis job payloads.

------------------------------------------------------------
3.9 RETRIES
------------------------------------------------------------

Temporary failure retry example:

Attempt 1: 30 seconds
Attempt 2: 2 minutes
Attempt 3: 10 minutes

Do not retry permanent errors:
Invalid token
Permission denied
Invalid Page
Unsupported media
Permanent API rejection

------------------------------------------------------------
3.10 IDEMPOTENCY
------------------------------------------------------------

Before publishing:
Check PostTarget status.

If already PUBLISHED:
Do not publish again.

Store provider post ID.

============================================================
FINAL PRINCIPLE
============================================================

START SIMPLE AND PROGRESSIVELY AUTOMATE.

PHASE 1 = MANAGE
PHASE 2 = SCHEDULE
PHASE 3 = AUTOMATE

The user must be able to start using the system immediately in Phase 1
without connecting any Facebook or LinkedIn API.

Phase 2 adds planning and scheduling.

Do not over-engineer Phase 1.
Do not require external API credentials until Phase 3.
